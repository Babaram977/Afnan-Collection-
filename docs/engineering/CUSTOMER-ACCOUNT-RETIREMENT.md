# Public customer account retirement

Owner decision, 20 November 2026 (Africa/Lagos): the storefront does not need a customer account experience. This focused change removes its UI without deleting data or changing administrator authentication.

- Desktop and mobile menus omit Account. The administrator-only Store Management entry and the administration header/Sections/Back to Store navigation are unchanged.
- `/account` returns a 302 redirect to `/`, including old order and return-to query bookmarks. The old profile, sign-in, saved-address, order-history and tracking UI no longer mounts. Redirecting does not sign anyone out.
- The dormant checkout UI no longer links to account tracking or fetches/offers saved addresses. Its shopping link returns to `/shop`. Checkout and payments remain disabled; no order/payment backend or configuration is changed.
- Existing customer records, credentials, sessions, saved addresses and historical orders remain intact. Owner-scoped data APIs and existing payment callbacks are retained for compatibility; a callback to `/account` now gracefully reaches the storefront. This is not approval to activate checkout/payments or introduce another customer portal.
- Admin components, the `/admin` route, authentication/session/role logic, migrations, Worker configuration and official logo bytes are unchanged. No production or other-project resource is accessed or modified by the local fixtures.

The new CI suite checks retired bookmarks, anonymous and signed-in navigation at 320/390/768/1440 px, the original logo, catalogue/bag controls, disabled commerce and customer authorization denial. A real locally minted customer session, saved address and historical order survive unchanged in a before/after database snapshot. Existing navigation, mobile-header, browser and bank-transfer fixture tests retain backend/order coverage without depending on removed account screens. Native administrator password-login regression remains a separate existing suite.

Local validation passed: 104 new account-retirement checks; 40 unit tests; 67 administrator-navigation and 12 native-login browser checks; 161 compact-header checks in each of Chromium and WebKit; 79 bank-transfer, 111 browser/accessibility, 201 storefront and 88 branding checks. Frozen install, typecheck, lint (zero errors/ten existing warnings), Worker build/package, unrestricted audit, Actionlint and diff checks passed. Local WebKit uses cached workspace libraries with the host-library preflight disabled because it only checks the system linker cache; actual WebKit tests still run. CI installs system dependencies and runs its normal WebKit checks. The exact PR/CI head is reported in the pull request. Screenshots are generated from isolated fixtures, not the production catalogue. No merge or production deployment is authorized by this task.
